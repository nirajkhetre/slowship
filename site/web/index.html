How it works

A night’s watch, in five steps.

Cheap first, careful last, so a whole night’s work stays small and the morning stays quiet.

  1. 1

    Find everything aboard.

    One pass over your lockfile, the folders your coding agents load skills from, and your editors’ MCP settings. Nothing to set up.

  2. 2

    Remember what it read.

    Every item is fingerprinted by its bytes. Anything unchanged since last night is skipped, and anything you cleared stays cleared until its code changes.

  3. 3

    Read the code, never run it.

    A pass over the syntax tree finds what the code can actually do: network calls, running programs, writing files, reading secrets, building code at runtime. Each fact keeps its file and line.

  4. 4

    Compare it with what it says.

    A small open model on your own laptop, gemma4 through Ollama, checks the description against the facts, one by one, and must cite the facts it means. Nothing is uploaded.

  5. 5

    Leave one verdict.

    Severity is decided in code. Only a combination found in code can hold the ship, and the model can never lower a hold, so a README that sweet-talks scanners gets nowhere.

    Safety

    Read, never run.

    A checker that starts the servers it checks has already lost. slowship keeps everything it reads in quarantine, sealed, and treats every word a package wrote as data.

    Nothing it reads is started

    No require, no install scripts, no MCP servers launched. Programs it uses get fixed arguments and no shell.

    The model lives on your laptop

    gemma4 runs through Ollama, on your machine. Without it, slowship runs on its rules alone and says so.

    Nothing is uploaded

    The report answers only this machine. The one thing that ever leaves is the morning ping you connect, with the verdict and nothing else.

    Clearing stays with you

    Your agent gets tools to check and watch, and none to clear. A package can’t talk its way past you.

    Against known malware

    On 200 skills from MalSkillBench, 100 malicious and 100 benign: a hold is usually right, 12 of 14. It catches about one malicious skill in eight with rules alone, and more as “worth a glance”. Most misses are attacks written as plain English, which slowship doesn’t read as code yet.

    What it can’t see

    • Code fetched or built while a program runs
    • What compiled code does, past its build record
    • TypeScript, and code inside markdown blocks
    • Prompt injection beyond four narrow patterns

    No findings is not proof of nothing. The report says so too.

    The model isn’t repeatable bit for bit: between two runs it moved 4 package verdicts by one step. Rules-only verdicts didn’t change at all. Every number here, and how to rerun it, is in Measured results.

    Get started

    Three commands. Then sleep.

    You need Node.js 22.19 or newer. Ollama is optional but recommended.

    1. Install it
      git clone https://github.com/nirajkhetre/slowship && cd slowship && npm install && npm link
    2. Give it a model (optional)
      ollama pull gemma4:e2b
    3. Keep watch in the project you’re about to ship
      slowship
